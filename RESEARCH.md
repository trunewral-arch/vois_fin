# RESEARCH — open-source ориентиры для Voice Expense

Дата исследования: **2026-11-01**. Время: ~15 минут, 4 параллельных субагента.
Проверялись GitHub-страницы, API (`license`, `commits`, `releases`), файлы `LICENSE` и исходники.
Звёзды и даты — на момент проверки, они меняются. Всё, что не удалось подтвердить, помечено как «не проверено».

> **Главное правило:** код без файла `LICENSE` не копируем вообще. AGPL/GPL — не копируем в закрытый продукт. MIT/BSD/Apache — можно, но с сохранением copyright-уведомления. Идеи, формулы и UX можно перенимать всегда, код — только по лицензии.

---

## 1. Что искали

IDEA.md описывает голосовой PWA-трекер расходов (8 категорий, Push-to-Talk, Web Speech API, IndexedDB/Dexie, Apple-стиль). Исследование — по трём смежным областям, которые понадобятся при развитии продукта:

1. **Досрочное погашение ипотеки** — расчёты, графики, сценарии «сократить срок vs уменьшить платёж».
2. **Учёт бюджета** — категории, лимиты, статистика, экспорт, офлайн/PWA.
3. **Финансовые цели** — целевая сумма, дедлайн, сколько откладывать в месяц, прогресс, what-if.
4. Бонусом — **русские числительные и голосовой парсинг**, потому что это ядро нашего продукта и самое рискованное место.

## 2. Пять лучших примеров

### 1) kostiuchenkoav/mortgage-calculator — эталон расчёта досрочки

**Ссылка:** https://github.com/kostiuchenkoav/mortgage-calculator

| Параметр | Значение |
|---|---|
| Стек | React 18 + TypeScript + Vite + Recharts, Vitest |
| Живость | 1 ★, последний коммит **2026-10-25**, не архив; проект маленький и свежий, issues/PR не проверялись |
| Лицензия | **MIT** (файл `LICENSE` + GitHub API) ✅ |

**Что уже реализовано.** Аннуитет и дифференцированный платёж, помесячный график, два режима досрочного погашения: `term` (платёж тот же, срок сокращается) и `payment` (срок тот же, платёж пересчитывается). Считаются переплата, общая выплата, фактический срок, первый/последний платёж, сводка по годам. Логика вынесена в чистые функции `src/lib/mortgage.ts`, есть тесты.

**Что взять.**
- Архитектуру «чистое расчётное ядро + тонкий UI»: `calculateSchedule(input) → { schedule, totalInterest, actualMonths }`.
- Типы режимов досрочки и URL-состояние (шаринг расчёта ссылкой).
- Годовую сводку и ленивую загрузку графика.
- Русскоязычный UI как референс терминов.

**Ограничения.** Поддерживается только **одно** досрочное погашение и только для аннуитета; нет изменения ставки, страховок, комиссий, налогового вычета.

### 2) gammaSpeck/expense-tracker (ExTrack) — ближайший по стеку трекер расходов

**Ссылка:** https://github.com/gammaSpeck/expense-tracker

| Параметр | Значение |
|---|---|
| Стек | React 18 + TypeScript + Vite + **Dexie.js (IndexedDB)** + Tailwind 4 + PWA |
| Живость | 12 ★, коммит **2026-10-23** (пуш 2026-11-01), релиз v1.9.0 (2026-09-15), 11 открытых issues, не архив |
| Лицензия | **MIT** ✅ |

**Что уже реализовано.** CRUD и дублирование расходов; категории с иконками Lucide и цветами, защищённая категория «Other», перенос транзакций при удалении категории; теги; вложения; аналитика (pie/bar, тренды по дням/неделям/месяцам, произвольный период, средний чек, топ-категория); полнотекстовый поиск; **CSV/JSON экспорт и импорт**, шифрованный бэкап; офлайн-first; тёмная тема; опциональный бэкап в Google Drive без своего бэкенда.

**Что взять.**
- Схему категории: `id + name + icon + color + isProtected` — ровно то, что нужно для 8 настраиваемых кнопок.
- Политику удаления категории: «перенести транзакции» vs «удалить каскадом».
- Набор метрик дашборда и **фиксированный формат CSV** (`Date, Time, Category, Description, Value, Tags, ...`) как контракт экспорта.
- Подтверждение, что Dexie + PWA — рабочий и достаточный стек для MVP.

**Ограничения.** Нет бюджетов/лимитов и регулярных платежей (в roadmap); нет i18n/русского; мобильный UX местами «desktop-адаптированный»; мало звёзд — мало внешней проверки.

### 3) actualbudget/actual — лучший пример целей внутри бюджета

**Ссылка:** https://github.com/actualbudget/actual

| Параметр | Значение |
|---|---|
| Стек | TypeScript + Node + React + SQLite, local-first sync |
| Живость | ~29 900 ★, коммиты почти ежедневно, релиз v26.10.0 (2026-10-02), ~93 открытых PR — очень живой |
| Лицензия | **MIT** ✅ |

**Что уже реализовано.** «Goal templates» прямо в бюджете: `#goal 5000`, `#template 5000 by 2027-12`, `#template 200 monthly`, `repeat every N months`, `up to`, `spend from`, приоритеты. Грамматика — `packages/loot-core/src/server/budget/goal-template.pegjs`. Месячный взнос считается в `category-template-context.ts` (`runBy`): разница месяцев до цели, прокрутка повторяющихся целей, деление остатка, распределение нескольких целей по приоритетам. UI показывает, сколько нужно забюджетировать в текущем месяце.

**Что взять.**
- UX «цель = шаблон»: пользователь задаёт сумму и дату, приложение само считает месячный взнос.
- Корректные edge cases: цель в прошлом, повторяющаяся цель, недобор/перерасход в прошлом месяце, несколько целей на одну категорию.
- Понятие `spend from` — цель финансируется не сразу, а с определённого месяца.

**Ограничения.** Нет сложного процента, инфляции и FIRE-логики — это бюджетные конверты. Движок завязан на `loot-core` и SQLite, вырвать его отдельно трудно; брать стоит идеи и формулы, а не код.

### 4) jamesmontemagno/app-fire-calculator (MyFireNumber) — математика финансовых целей

**Ссылка:** https://github.com/jamesmontemagno/app-fire-calculator

| Параметр | Значение |
|---|---|
| Стек | .NET MAUI (C#) + React 19 / TypeScript / Vite / Recharts, есть веб-версия |
| Живость | ~49 ★, коммит **2026-10-24**, 0 issues, 1 PR, формальных релизов нет |
| Лицензия | **MIT** ✅ |

**Что уже реализовано.** `FutureValue`, `PresentValue`, `YearsToTarget`, `YearsToFireTarget` (closed-form + бисекция, два режима роста взносов), `GenerateProjections` (годовая траектория портфеля и реального баланса), `CalculateWithdrawal` (drawdown с индексируемыми изъятиями). Отдельно: FIRE number, Coast/Lean/Fat/Barista FIRE, **reverse FIRE** — сколько нужно откладывать в месяц, чтобы прийти к цели к дате. UI: прогресс-бар с вехами 25/50/75/100% и статусами on track / off track.

**Что взять.**
- Формулы: `FI = annualExpenses / SWR`; `Coast = FI / (1 + realReturn)^years`; `realReturn = (1 + nominal)/(1 + inflation) − 1`.
- Reverse-калькулятор как отдельный экран цели.
- Разделение «сегодняшние деньги» vs номинальные значения.
- Прогресс-бар с вехами и понятным статусом — сильный, но простой UX.

**Ограничения.** Детерминированная модель с постоянной доходностью, без волатильности и Monte Carlo. Часть логики дублируется на C# и TS (есть тесты на parity, но риск расхождений).

### 5) HenintsoaPaul/poketra-vy — готовый контракт голосового ввода

**Ссылка:** https://github.com/HenintsoaPaul/poketra-vy

| Параметр | Значение |
|---|---|
| Стек | Flutter + Riverpod + Hive + `speech_to_text` + `fl_chart`, есть web-сборка |
| Живость | 6 ★, **36 открытых issues**, 74 коммита, последний коммит 2026-04-16, релизов нет — сырой, но не мёртвый |
| Лицензия | **MIT** ✅ |

**Что уже реализовано.** Голосовой ввод фраз («10000 for lunch», «5000 for transport yesterday»), визуализатор волны, **эвристический парсер с документированными правилами**: сумма — первое число в строке; категория — первое совпадение с названием категории, иначе `misc`; «yesterday» → вчера, иначе сегодня; описание — весь текст. Есть экран подтверждения с редактированием, pie-chart по категориям, группировка по датам, чипы-фильтры.

**Что взять.**
- Сам контракт парсера и порядок правил — он напрямую переносится на Web Speech API.
- Flow «сказал → увидел разобранное → поправил → сохранил» (совпадает с баннером подтверждения из IDEA.md).
- Связывание категорий по `id`, чтобы переименование не ломало историю.
- Таблицу тест-кейсов, включая провальные («food today» → null), как основу для наших тестов.

**Ограничения.** Flutter, не PWA-first; парсер только английский — русские падежи, «полторы тысячи» и валютные слова придётся добавлять самим; нет бюджетов и экспорта.

## 5. Выводы для Voice Expense

**Что перенимаем как идеи (без копирования кода):**

1. **Ядро расходов** — схема ExTrack: категория `{id, name, icon, color, isProtected}`, фиксированный CSV-контракт, метрики дашборда. Наш стек (React + Vite + Dexie + PWA) уже подтверждён рабочим примером.
2. **Цели** — модель Actual: `targetAmount`, `currentAmount`, `targetDate`, `monthlyNeeded`, edge cases; для инвестиционных целей — формулы app-fire-calculator (`FI = expenses / SWR`, reverse-solve месячного взноса).
3. **Досрочка ипотеки** — если добавляем модуль: чистые функции + два режима (`term` vs `payment`) + обязательное сравнение с базовым сценарием без досрочек. Событийная модель Paydown.js — хороший ориентир для нескольких досрочек и изменения ставки.
4. **Голос** — контракт Poketra-Vy: сумма = первое число, категория = лучший матч, остаток = описание, экран подтверждения. Но правила для русского пишем сами.

**Что придётся делать самим (готового нет):**
- **Русский парсер сумм**: ни одна JS/TS-библиотека не решает «слова → число»; найденные npm-пакеты делают только обратное. Нужны «полтора/полторы», валютные слова («рублей», «копеек»), разговорные единицы («косарь», «сотка») и отделение суммы от описания.
- **Лимиты бюджетов** в офлайн-PWA: сильный референс только Ocular, и он серверный — модель «лимит + перенос остатка» придётся реализовать на Dexie.
- **Налоговый вычет, маткапитал, страховки, комиссии** для ипотеки — этого нет ни в одном найденном проекте; это потенциальное преимущество.

**Чего избегаем:**
- Копирования кода из проектов без `LICENSE` и из AGPL/GPL/NC.
- Зависимости от облачных voice-API (Speechly и подобных): в IDEA.md правильно выбран Web Speech API.
- Тяжёлых серверных архитектур (Firefly III, MoneyMatter, Ocular) на старте — они противоречат принципу «данные только на устройстве».
